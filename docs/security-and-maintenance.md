# 운영 제한과 개선 우선순위

## 적용한 보호 장치

- 기본 서버 주소는 `127.0.0.1`. LAN 공개는 `HOST=0.0.0.0`으로 명시한다. 기존 `.env`의 HOST 설정은 유지되므로 확인한다.
- AI 요청은 모든 AI 경로를 합산해 IP별 시간당 12회, 서버 전체 24시간당 100회로 제한한다. `.env`의 `AI_REQUESTS_PER_HOUR`, `AI_TOTAL_REQUESTS_PER_DAY`로 조정한다. 실제 토큰 비용 한도는 아니며 실패한 요청도 집계한다.
- 모든 POST 요청에 IP별 분당 60회 제한을 추가한다. 조회는 IP와 대상 경로별 30분당 1회다. 좋아요와 리뷰는 각각 IP별 분당 10회이며 모든 대상을 합산한다. 좋아요 취소와 리뷰 수정도 이 예산 내에서 즉시 가능하다. UUID를 바꾸어도 제한되며 같은 공유기 사용자도 제한을 공유한다.
- 초과 요청은 HTTP 429와 `Retry-After` 초 단위를 반환한다. 전달된 `X-Forwarded-For`를 신뢰하지 않는다.
- 카운터는 메모리에만 보관하며 만료 항목을 제거하고 크기를 제한한다. 재시작하면 초기화된다. 여러 서버 배포에는 Redis 등 공유 제한 저장소와 인증이 필요하다. 역방향 프록시 뒤에서는 프록시 IP 기준으로 합산된다.
- 깨진 `CookingHelper/` gitlink를 제거했다. 기존 중첩 체크아웃은 로컬 파일을 보존하고 ignore 처리했다.
- 앱 저장 JSON이 손상되면 `.corrupt` 키에 원본을 보관하고 레거시 데이터 또는 기본값으로 복구한다.
- 오류 화면, 비 JSON API 응답 처리, GitHub Actions 타입 검사·빌드·테스트를 추가했다.

## 후속 기능의 구현 순서

1. 작성자 인증 또는 서버 발급 소유권 증명 도입 후 글·댓글 수정/삭제 및 신고 관리. 클라이언트 UUID만으로 삭제 권한을 부여하지 않는다.
2. 조리 타이머 로컬 알림과 화면 유지. 실제 기기에서 권한 거부·백그라운드·취소·재시작 동작을 함께 확인한다.
3. 저장 레시피·설정·요리 기록의 버전 있는 내보내기/가져오기와 입력 검증.
4. Context 분리 및 화면/컨트롤러 분할, 포맷터·린트 도입.
5. JSON 파일에서 트랜잭션 DB로 마이그레이션, 기존 데이터 백업과 이전 검증.
6. 출시용 아이콘·스플래시와 발표 자료/중복 이미지 정리.

소비기한 정렬·임박 표시·재료 우선 추천과 레시피 카탈로그 메모리 인덱스는 기존 코드에 구현돼 있어 유지했다.

## 검증

`npm run typecheck`, `npm test`. `npm test`와 `npm run test:spring`은 각각 `pretest`와 `pretest:spring`에서 Gradle `build`를 먼저 실행한다. 빌드 실패 시 테스트를 실행하지 않는다. CI도 같은 흐름을 사용한다. `node --test`를 직접 실행하면 이 빌드 단계가 생략되므로 해당 명령은 최신 jar를 준비한 경우에만 사용한다.

통합 테스트는 실제 OpenAI 대신 로컬 fixture를 사용한다. UUID 변경 및 위조 전달 헤더로 제한을 우회할 수 없는지 검증한다.
